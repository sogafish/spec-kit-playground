## 実行フロー (/plan コマンド範囲)
```
1. 入力パスから機能仕様を読み込み
   → 見つからない場合: ERROR "仕様書が{パス}にありません"

   → コンテキストからプロジェクトタイプを検出（web=frontend+backend、mobile=app+api）

3. 憲法文書の内容に基づいて憲法チェック セクションを記入
4. 憲法チェック セクションを評価
   → 違反が存在する場合: 複雑性追跡に文書化

   → 進捗追跡を更新: 初期憲法チェック
5. Phase 0 → research.md を実行
   → 要明確化が残っている場合: ERROR "未解決事項を解決"
6. Phase 1 → contracts、data-model.md、quickstart.md、エージェント固有テンプレートファイル（例：Claude Code用CLAUDE.md）を実行

   → 進捗追跡を更新: デザイン後憲法チェック
8. Phase 2 を計画 → タスク生成アプローチを記述（tasks.mdは作成しない）
9. STOP - /tasks コマンド準備完了
```

**重要**: /plan コマンドは手順7で停止。Phase 2-4は他のコマンドで実行：
- Phase 2: /tasks コマンドがtasks.mdを作成
- Phase 3-4: 実装実行（手動またはツール経由）

## 概要
React Routerを使用したマルチページ対応のWebベースオセロゲーム。ホーム、ゲームモード選択、ゲームプレイ、結果、統計の各ページ間でのスムーズなナビゲーションと、ブラウザ履歴対応、URL直接アクセス、ゲーム状態保持を実現。CSS-in-JS（@vanilla-extract/css）による美しいUI、i18nextによる国際化対応、複数AI難易度レベルでの世界最高品質のオセロ体験を提供。

## 技術コンテキスト
**言語/バージョン**: TypeScript 5.0+
**主要依存関係**: React 18+, React Router 6+, @vanilla-extract/css, i18next
**ストレージ**: localStorage（ゲーム状態・統計・設定用）
**テスト**: Jest, React Testing Library, Playwright（E2E）
**対象プラットフォーム**: モダンWebブラウザ（Chrome 100+, Firefox 100+, Safari 15+）
**プロジェクトタイプ**: single（React SPAプロジェクト）
**パフォーマンス目標**: 初回ロード <3秒、ページ遷移 <300ms、ゲーム操作レスポンス <100ms
**制約**: オフライン対応（PWA）、モバイルレスポンシブ、アクセシビリティ対応（WCAG 2.1 AA）
**規模/スコープ**: 5つの主要ページ、10-15コンポーネント、AI思考エンジン統合

## Phase 0: アウトライン & 研究
1. **技術コンテキストから不明点を抽出**:
   - 依存関係の具体的バージョン要件
   - AI思考エンジンのアルゴリズム選択
   - PWA実装アプローチ
   - アクセシビリティ要件の詳細

2. **研究エージェントの生成と派遣**:
   ```
   各不明点について:
     タスク: "{機能コンテキスト}における{不明点}の研究"
   各技術選択について:
     タスク: "{ドメイン}における{技術}のベストプラクティス発見"
   ```

3. **調査結果の統合** を `research.md` に以下の形式で記録:
   - 決定: [選択したもの]
   - 根拠: [選択理由]
   - 検討した代替案: [評価した他の選択肢]

**出力**: すべての要明確化を解決した research.md

## Phase 1: デザイン & 契約
*前提条件: research.md完了*

1. **機能仕様からエンティティを抽出** → `data-model.md`:
   - エンティティ名、フィールド、関係
   - 要件からの検証ルール
   - 該当する場合の状態遷移

2. **機能要件からAPIコントラクトを生成**:
   - 各ユーザーアクション → エンドポイント
   - 標準的なREST/GraphQLパターン使用
   - OpenAPI/GraphQLスキーマを `/contracts/` に出力

3. **コントラクトからコントラクトテストを生成**:
   - エンドポイント毎に1つのテストファイル
   - リクエスト/レスポンススキーマの検証
   - テストは失敗すること（まだ実装なし）

4. **ユーザーストーリーからテストシナリオを抽出**:
   - 各ストーリー → 統合テストシナリオ
   - クイックスタートテスト = ストーリー検証手順

5. **エージェントファイルの段階的更新**（O(1)操作）:
   - AIアシスタント用に `.specify/scripts/bash/update-agent-context.sh claude` を実行
   - 存在する場合: 現在の計画から新しい技術のみ追加
   - マーカー間の手動追加を保持
   - 最近の変更を更新（最新3つを保持）
   - トークン効率のため150行以下に保持
   - リポジトリルートに出力

**出力**: data-model.md、/contracts/*、失敗テスト、quickstart.md、エージェント固有ファイル

## Phase 2: タスク計画アプローチ
*このセクションは/tasksコマンドが行うことを記述 - /plan中は実行しない*
