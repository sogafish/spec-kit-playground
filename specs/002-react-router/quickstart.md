# クイックスタートガイド

**プロジェクト**: React Routerベースオセロゲーム
**作成日**: 2025-09-17
**バージョン**: 1.0

## 概要

本文書では、React Routerベースのオセロゲームアプリケーションのクイックスタート手順を提供します。ユーザーストーリーから抽出されたテストシナリオに基づき、各ページ遷移の基本フロー、ゲームプレイの手順、エラーケースの対応方法を説明します。

## 基本フロー

### 1. アプリケーション起動からゲーム開始まで

#### シナリオ1: 初回訪問ユーザーのゲーム開始

**前提条件:**
- ブラウザでアプリケーションにアクセス
- 初回訪問ユーザー

**手順:**
1. ホームページ（`/`）にアクセス
2. "ゲーム開始" ボタンをクリック
3. ゲームモード選択ページ（`/game-mode`）に遷移
4. "AI対戦" を選択
5. AI難易度を "中級" に設定
6. "ゲーム開始" ボタンをクリック
7. ゲームプレイページ（`/play`）に遷移

**期待結果:**
- 各ページが正しく表示される
- URLが適切に変更される
- ゲーム状態が正しく初期化される
- 8×8のオセロボードが表示される
- 黒石のプレイヤーターンで開始

**検証ポイント:**
- ページタイトルが正しく設定される
- ナビゲーション履歴が正しく記録される
- ゲーム設定が保持される

#### シナリオ2: 継続ユーザーのクイックスタート

**前提条件:**
- 以前にゲームプレイ経験あり
- ローカルストレージに設定が保存済み

**手順:**
1. ホームページアクセス
2. "前回の設定でゲーム開始" ボタンをクリック
3. ゲームプレイページに直接遷移

**期待結果:**
- 前回の設定（AI難易度、音声設定など）が復元される
- ゲームモード選択をスキップして直接ゲーム開始
- ユーザー統計が表示される

### 2. ゲームプレイの基本フロー

#### シナリオ3: 標準的なゲームプレイ

**前提条件:**
- ゲームプレイページ（`/play`）にいる
- AI対戦モード、中級難易度

**手順:**
1. ボード上の有効な手（緑色のマーク）をクリック
2. 黒石が配置される
3. 裏返された白石がアニメーション表示される
4. AIの思考時間待機
5. AIが手を実行（白石配置）
6. 手順3-5を繰り返し

**期待結果:**
- クリックした位置に石が正しく配置される
- オセロのルールに従って石が裏返される
- スコアが正しく更新される
- ターン表示が正しく切り替わる
- AI思考中はローディング表示

**検証ポイント:**
- 無効な手をクリックしてもエラーにならない
- ゲーム状態がリアルタイムで更新される
- アニメーションが滑らか

#### シナリオ4: ゲーム完了からリザルト表示

**前提条件:**
- ゲーム終盤でもうすぐ終了

**手順:**
1. 最後の有効な手を実行
2. ゲーム終了条件を満たす（全マス埋まる or 両者パス）
3. 自動的に結果ページ（`/results/:gameId`）に遷移
4. "統計を見る" リンクをクリック
5. 統計ページ（`/stats`）に遷移

**期待結果:**
- ゲーム終了が正しく検出される
- 勝敗判定が正確
- 結果ページに最終スコア表示
- 統計データが更新される
- ゲーム履歴に記録される

### 3. ページ遷移とナビゲーション

#### シナリオ5: ブラウザナビゲーション対応

**前提条件:**
- ゲームプレイページにいる
- ゲーム進行中

**手順:**
1. ブラウザの戻るボタンをクリック
2. ゲームモード選択ページに戻る
3. ブラウザの進むボタンをクリック
4. ゲームプレイページに復帰

**期待結果:**
- ページ遷移が正しく動作
- ゲーム状態が保持される
- 進行中のゲームが継続可能
- ページタイトルが正しく更新

**検証ポイント:**
- URL変更が正しく反映される
- ゲーム状態の整合性確保
- メモリリークが発生しない

#### シナリオ6: 直接URL入力でのアクセス

**前提条件:**
- 進行中のゲームが存在

**手順:**
1. ブラウザのアドレスバーに `/play/game123` を直接入力
2. Enterキーを押下

**期待結果:**
- 該当ゲームが存在する場合、ゲーム状態が復元される
- 該当ゲームが存在しない場合、エラーページに遷移
- 適切なローディング表示

### 4. 統計・履歴機能

#### シナリオ7: 統計情報の確認

**前提条件:**
- 複数ゲームのプレイ履歴あり

**手順:**
1. メニューから "統計" をクリック
2. 統計ページ（`/stats`）に遷移
3. "勝率" タブを選択
4. "AI難易度別" フィルタを適用
5. "過去30日" の期間を選択

**期待結果:**
- 統計データが正しく表示される
- フィルタが正しく動作
- グラフが適切に描画される
- データの整合性が保たれる

#### シナリオ8: ゲーム履歴の詳細確認

**前提条件:**
- 統計ページにいる

**手順:**
1. "ゲーム履歴" タブをクリック
2. 特定のゲームエントリをクリック
3. ゲーム詳細モーダルが表示される
4. "棋譜再生" ボタンをクリック
5. 手順を順次再生

**期待結果:**
- ゲーム履歴が正しく表示される
- 詳細情報が正確
- 棋譜再生が滑らかに動作
- 任意の手順にジャンプ可能

## エラーケースの対応

### シナリオ9: 404エラーハンドリング

**前提条件:**
- アプリケーション正常動作中

**手順:**
1. ブラウザのアドレスバーに存在しないURL `/invalid-page` を入力
2. Enterキーを押下

**期待結果:**
- エラーページ（`/error`）が表示される
- "ページが見つかりません" メッセージ表示
- ホームページへのリンクが提供される
- 404 HTTPステータスコードが返される

**検証ポイント:**
- エラーページが適切にスタイルされている
- SEO対応のメタタグが設定される
- エラー情報がログに記録される

### シナリオ10: ネットワークエラー対応

**前提条件:**
- ゲームプレイ中
- AI思考リクエスト実行中

**手順:**
1. ネットワーク接続を一時的に無効化
2. AI手の実行を待機
3. エラーが発生

**期待結果:**
- エラーメッセージが表示される
- リトライボタンが提供される
- ゲーム状態がローカルに保持される
- ネットワーク復旧後に継続可能

### シナリオ11: ページリロード時の状態復元

**前提条件:**
- ゲーム進行中
- 手順が5手以上進んでいる

**手順:**
1. ブラウザのリロードボタンをクリック（F5キー）
2. ページが再読み込みされる

**期待結果:**
- ゲーム状態が正しく復元される
- 進行中のターンが維持される
- 履歴が保持される
- ユーザー設定が復元される

**検証ポイント:**
- ローカルストレージからの復元
- セッションストレージの活用
- データの整合性確保

### シナリオ12: 複数タブでの同時アクセス

**前提条件:**
- タブ1でゲーム進行中

**手順:**
1. 新しいタブを開く
2. 同じアプリケーションにアクセス
3. タブ2でも新しいゲームを開始
4. タブ1に戻る

**期待結果:**
- 各タブで独立したゲーム状態管理
- タブ間でのデータ競合が発生しない
- 統計情報は正しく共有される
- メモリ使用量が適切

## パフォーマンステスト

### シナリオ13: 大量データでの動作確認

**前提条件:**

**手順:**
1. 統計ページにアクセス
2. "全期間" の統計を表示
3. ゲーム履歴を最初から最後まで閲覧

**期待結果:**
- ページロード時間が3秒以内
- スクロール操作が滑らか
- グラフ描画が5秒以内
- メモリ使用量が適切な範囲

### シナリオ14: 連続ゲームプレイ

**前提条件:**
- アプリケーション起動直後

**手順:**
1. 連続で10ゲームプレイ
2. 各ゲームは最後まで完了
3. 結果確認と新ゲーム開始を繰り返し

**期待結果:**
- メモリリークが発生しない
- パフォーマンスが劣化しない
- データ保存が正しく動作
- UI反応性が維持される
